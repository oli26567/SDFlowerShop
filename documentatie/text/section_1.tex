\section{Analysis phase - Use cases \& requirements}

\subsection{Functional requirements}

\par Functional requirements describe the operations that the system must perform.

\par These requirements define the services the system provides and the expected system behavior. You usually derive them from the problem statement.

Examples of functional requirements include:

\begin{itemize}
\item The system must allow users to authenticate.
\item The system must allow users to create, update and delete records.
\item The system must allow users to search or filter data.
\end{itemize}

\par For this laboratory, non-functional requirements are out of scope, but you can optionally exercise specifying some that are related to the assignment topic (such as security requirements, scalability, performance etc.).

\subsection{Use cases}
\par Use cases describe in text the interactions between actors and the system in order to accomplish specific tasks.

\par Each use case should include:

\begin{itemize}
\item The actor initiating the interaction
\item A description of the task being performed
\item The result of a successful interaction
\end{itemize}

\par Do not forget to include a use case diagram here!

\section{Design phase}

\subsection{Architecture overview}

\par This subsection presents the high-level architecture of the application. It should describe how the system is divided into major components such as client applications, backend services and the database.

\par The chosen architectural style such as client-server or layered architecture may be discussed here, with the advantages and disadvantages it brings.

\subsection{Entity-relationship diagram}

\par This subsection describes the database schema used by the application.

\par The entity-relationship diagram should illustrate the structure of the database and the relationships between entities.

\par Each table should be described briefly, including:

\begin{itemize}
\item Table purpose
\item Important attributes
\item Relationships with other tables
\end{itemize}

\subsection{Component X}

\par This subsection is an example to describe one of the main components of the system.This could represent the server application, a backend service or a specific module of the system.

\par The description should include the responsibilities of the component and how it interacts with other parts of the system.

\subsection{Component Y}

\par This subsection describes another component of the system, such as the client application or an additional service layer.

\par Explain its role in the architecture and the type of functionality it provides.

\subsection{Design patterns}

\par This subsection explains the design patterns used in the system.

\par For each pattern you should describe:

\begin{itemize}
\item The category of the pattern (creational, structural, behavioral)
\item The problem it solves
\item The classes involved in the implementation
\end{itemize}

\subsection{Class diagrams}

\par Class diagrams describe the static structure of the system by presenting classes, attributes, methods and relationships between classes.

\par This section should include one or more class diagrams illustrating the internal organization of the system components.

\subsection{Sequence diagrams}

\par Sequence diagrams illustrate how objects interact during the execution of a particular use case.

\par They show the order of method calls and message exchanges between system components.

\section{Implementation phase - Application}

\subsection{Tools and technologies}
\par This subsection presents the technology stack used to implement the application.

\par You should describe the main tools and technologies used during development, such as:

\begin{itemize}
\item Programming language
\item Database management system
\item Frameworks or third-party libraries
\item Communication protocols
\end{itemize}

\par You should also explain the reasons for choosing these technologies.

\subsection{Application structure}

\par This subsection describes the structure of the source code and how the project is organized. For example, you may describe packages, modules, or layers used in the application.

\subsection{User manual}
\par Here you should present the graphical user interface of the application and explain how users interact with the system.

\par The user manual should describe how a user can access the main functionalities of the application depending on their role.

\par Don't be shy to include screenshots of the interface whenever necessary to illustrate the different features available to users!

\section{Testing and validation}

\par This section describes the methods used to verify that the application works correctly.

\par Testing should include unit testing specific to the programming language/framework you choose!

\par The goal is to demonstrate that the implemented system satisfies the requirements defined in the analysis phase.
